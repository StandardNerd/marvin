# VEC-001: Environment, System Boot & Health Verification

**Identifier:** `VEC-001`  
**Category:** Infrastructure & System Health  
**Target Systems:** Rails 8 Application, Python ML Worker (FastAPI), Redis, SQLite, Docker Compose  

---

## 1. Objective

Verify that all system components (Rails application, Python ML worker, background job queue, and database) boot cleanly, expose appropriate health endpoints, load schema migrations, and communicate across boundaries without errors.

---

## 2. Prerequisites & Environment

- Ruby 3.4.0+
- Rails 8.1.4
- SQLite 3
- Python 3.11+
- Node.js (for Tailwind builds) or standalone Tailwind CLI
- `curl`, `jq`, or any standard HTTP client

---

## 3. Test Cases & Procedures

### TC-001.1: Rails Health Endpoint Check
* **Objective:** Verify Rails provides a functional `/up` endpoint for load balancers and orchestrators.
* **Procedure:**
  ```bash
  curl -s -i http://localhost:3000/up
  ```
* **Expected Result:**
  - HTTP Status: `200 OK`
  - Response body contains green health HTML or 200 status code indicating database and subsystems are responsive.

### TC-001.2: Python ML Worker Health Endpoint
* **Objective:** Verify the FastAPI ML Worker starts and returns GPU capability status.
* **Procedure:**
  ```bash
  curl -s http://localhost:8000/health | jq .
  ```
* **Expected Result:**
  - HTTP Status: `200 OK`
  - Response format:
    ```json
    {
      "status": "ok",
      "gpu_available": false,
      "gpu_name": null,
      "active_jobs": 0
    }
    ```
  - If executed on a host with NVIDIA CUDA configured, `gpu_available` should report `true` with device name in `gpu_name`.

### TC-001.3: Database Migrations & Schema Status
* **Objective:** Ensure all 8 domain model migrations are cleanly applied with correct indexes and constraints.
* **Procedure:**
  ```bash
  rails db:migrate:status
  ```
* **Expected Result:**
  - All migrations display status `up`:
    - `CreateUsers`
    - `CreateProjects`
    - `CreateDatasets`
    - `CreateDatasetExamples`
    - `CreateTrainingRuns`
    - `CreateTrainingMetrics`
    - `CreateEvaluations`
    - `CreateModelArtifacts`
    - `CreateActiveStorageTables`

### TC-001.4: Asset Pipeline & Tailwind Compilation
* **Objective:** Verify Tailwind CSS compiles without errors and asset files are accessible.
* **Procedure:**
  ```bash
  rails tailwindcss:build
  ```
* **Expected Result:**
  - Exit code `0`.
  - File `app/assets/builds/tailwind.css` generated and contains base Tailwind styles.

### TC-001.5: Docker Compose Multi-Container Orchestration
* **Objective:** Verify that `docker compose config` is valid and services are configured with healthchecks.
* **Procedure:**
  ```bash
  docker compose config --services
  ```
* **Expected Result:**
  - Outputs:
    ```text
    ml-worker
    rails
    redis
    ```
  - Internal environment variables `ML_WORKER_URL`, `ML_WORKER_API_KEY`, `RAILS_INTERNAL_URL` are properly mapped.

---

## 4. Pass / Fail Acceptance Criteria

- [ ] `/up` returns HTTP 200 within 500ms.
- [ ] ML Worker `/health` returns status `ok` and active job count.
- [ ] No pending database migrations.
- [ ] `rails tailwindcss:build` completes without missing stylesheet warnings.
- [ ] Docker compose services boot without networking or port conflicts.
