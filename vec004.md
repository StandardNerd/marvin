# VEC-004: Dataset Ingestion & Validation Pipeline Verification

**Identifier:** `VEC-004`  
**Category:** Data Ingestion & Background Jobs  
**Target Systems:** `DatasetsController`, `DatasetProcessingJob`, Active Storage, `Dataset`, `DatasetExample` Models  

---

## 1. Objective

Verify that JSONL dataset files uploaded via Active Storage are processed asynchronously, parsed line-by-line, validated against the chat message schema, recorded into `DatasetExample` records, and gracefully handle individual malformed lines without failing the entire ingestion process.

---

## 2. Test Cases & Procedures

### TC-004.1: Valid JSONL Ingestion
* **Objective:** Verify standard chat-formatted JSONL is correctly parsed and sets dataset status to `ready`.
* **Input Dataset:**
  ```json
  {"messages":[{"role":"user","content":"How do I reset my password?"},{"role":"assistant","content":"Click Forgot Password on the login page."}]}
  {"messages":[{"role":"user","content":"Where are the API keys located?"},{"role":"assistant","content":"Under Settings > Developer > API Keys."}]}
  ```
* **Procedure:**
  1. POST `/projects/:project_id/datasets` with the above file attached.
  2. Execute `DatasetProcessingJob.perform_now(dataset.id)`.
* **Expected Result:**
  - Status transitions: `uploaded` ➔ `processing` ➔ `ready`.
  - `dataset.examples_count` is updated to `2`.
  - Two `DatasetExample` records created with `validation_errors: nil` and `accepted: nil` (needs review).

### TC-004.2: Mixed Valid and Malformed JSON Lines
* **Objective:** Ensure individual malformed JSON lines are flagged with errors without crashing the entire import.
* **Input Dataset:**
  ```text
  {"messages":[{"role":"user","content":"Hello"},{"role":"assistant","content":"Hi"}]}
  {this is invalid json}
  {"messages":[{"role":"user","content":"Another valid question"},{"role":"assistant","content":"Valid response"}]}
  ```
* **Procedure:**
  1. Process the above file with `DatasetProcessingJob`.
* **Expected Result:**
  - `Dataset` status becomes `ready`.
  - Line 2 creates a `DatasetExample` with `validation_errors: ["Line 2: Invalid JSON - ..."]`.
  - Valid lines 1 and 3 are created successfully without validation errors.

### TC-004.3: Missing Roles and Missing User/Assistant Pairs
* **Objective:** Verify schema rules: requires array of messages, valid roles (`system`, `user`, `assistant`), and at least one user and one assistant message.
* **Input Dataset:**
  ```json
  {"messages":[{"role":"invalid_role","content":"Test"}]}
  {"messages":[{"role":"user","content":"Only a question, no answer"}]}
  ```
* **Procedure:**
  1. Process the file with `DatasetProcessingJob`.
* **Expected Result:**
  - Example 1 records validation error: `"Message 1: invalid role 'invalid_role'"`.
  - Example 2 records validation error: `"Must have at least one user and one assistant message"`.

### TC-004.4: Missing Attached File Handling
* **Objective:** Ensure safe failure mode if a dataset processing job is triggered without an attached file.
* **Procedure:**
  1. Create a `Dataset` without attaching a file.
  2. Run `DatasetProcessingJob.perform_now(dataset.id)`.
* **Expected Result:**
  - Dataset status is updated to `failed`.
  - Job logs an error without throwing unhandled exceptions.

### TC-004.5: Reprocess Action
* **Objective:** Verify that users can re-trigger processing on an uploaded dataset via `POST /projects/:project_id/datasets/:id/process_file`.
* **Procedure:**
  1. Send POST to `/projects/:project_id/datasets/:id/process_file`.
* **Expected Result:**
  - Dataset status resets to `uploaded`.
  - `DatasetProcessingJob` is re-enqueued.
  - User redirected to dataset show page with flash message `"Reprocessing started."`.

---

## 3. Pass / Fail Acceptance Criteria

- [ ] Valid JSONL files transition to status `ready`.
- [ ] Active Storage stores original file untouched.
- [ ] `examples_count` matches total processed lines.
- [ ] Invalid lines do not abort the job; errors are captured in `validation_errors` JSON column.
- [ ] All tests in `test/jobs/dataset_processing_job_test.rb` pass.
