# VEC-006: QLoRA Configuration & Job Submission Verification

**Identifier:** `VEC-006`  
**Category:** Training Configuration & Job Dispatch  
**Target Systems:** `TrainingRunsController`, `TrainingRun` Model, `TrainingRunJob`, `MlWorkerClient` Service  

---

## 1. Objective

Verify that users can configure all key QLoRA hyperparameters (LoRA rank, alpha, dropout, learning rate, epochs, batch size, gradient accumulation, sequence length, and quantization), that configurations are validated and stored immutably once training begins, and that `TrainingRunJob` accurately constructs and submits the job request to the Python ML worker.

---

## 2. Test Cases & Procedures

### TC-006.1: QLoRA Form Defaults & Collapsible Section
* **Objective:** Verify new experiment form initializes with standard QLoRA defaults and interactive collapse.
* **Procedure:**
  1. Navigate to `/projects/:project_id/training_runs/new`.
  2. Inspect default values in the form.
* **Expected Result:**
  - `Base Model`: Inherited from Project (e.g. `Qwen/Qwen3-8B`).
  - `LoRA Rank (r)`: `16`
  - `LoRA Alpha`: `32`
  - `LoRA Dropout`: `0.05`
  - `Learning Rate`: `0.0002`
  - `Epochs`: `3`
  - `Batch Size`: `1`
  - `Gradient Accumulation`: `8`
  - `Max Sequence Length`: `2048`
  - `Quantization`: `4bit_nf4`
  - Stimulus `collapse_controller.js` toggles advanced config visibility.

### TC-006.2: Accepted Examples Guardrail
* **Objective:** Ensure a training run cannot be started if the selected dataset has 0 accepted examples.
* **Procedure:**
  1. Create a dataset where all examples are `rejected` or `needs_review`.
  2. Create a pending training run linked to this dataset.
  3. Attempt to start the training run (`POST .../training_runs/:id/start`).
* **Expected Result:**
  - Request is blocked.
  - Redirected with alert: `"Dataset must have at least one accepted example."`.
  - Status remains `pending`.

### TC-006.3: State Transition from Pending to Queued
* **Objective:** Verify starting an experiment transitions status and enqueues `TrainingRunJob`.
* **Procedure:**
  1. On a valid pending experiment, submit `POST .../training_runs/:id/start`.
* **Expected Result:**
  - `training_run.status` updates to `queued`.
  - `TrainingRunJob` is enqueued into Active Job queue (`queue_as :default`).
  - Flash notice displays: `"Training queued."`.

### TC-006.4: Immutability Once Active
* **Objective:** Ensure configuration cannot be edited after training starts.
* **Procedure:**
  1. Transition a training run to `running`.
  2. Send PATCH `/projects/:project_id/training_runs/:id` with modified configuration.
* **Expected Result:**
  - Controller rejects the update with alert: `"Cannot edit a non-pending experiment."`.
  - Configuration JSON remains unchanged in SQLite.

### TC-006.5: ML Worker HTTP Submission
* **Objective:** Verify `MlWorkerClient#create_training_run` formats the HTTP payload and headers correctly.
* **Procedure:**
  1. Inspect payload constructed by `MlWorkerClient`:
     - `training_run_id`: string
     - `base_model`: string
     - `dataset_url`: points to `/api/v1/datasets/:id/export.jsonl`
     - `configuration`: dictionary of hyperparameters
     - `callback_url`: points to `/api/v1/training_callbacks/:id`
     - Headers include `X-API-Key`
* **Expected Result:**
  - Payload matches Python worker's `TrainingRequest` Pydantic schema in `ml_worker/app/schemas.py`.

---

## 3. Pass / Fail Acceptance Criteria

- [ ] All 10 QLoRA parameters configurable in UI and persisted in `configuration` JSON.
- [ ] Training cannot be launched with zero accepted dataset examples.
- [ ] Active training runs cannot be edited or deleted.
- [ ] `TrainingRunJob` properly delegates to `MlWorkerClient`.
- [ ] All tests in `test/models/training_run_test.rb` and `test/integration/training_runs_flow_test.rb` pass.
