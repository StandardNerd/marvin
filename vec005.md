# VEC-005: Dataset Curation & Bulk Actions Verification

**Identifier:** `VEC-005`  
**Category:** Frontend & Data Curation  
**Target Systems:** `DatasetsController`, `DatasetExamplesController`, Stimulus `bulk_select_controller.js`, Views (`datasets/show.html.erb`, `dataset_examples/edit.html.erb`)  

---

## 1. Objective

Verify the dataset curation user interface, ensuring developers can inspect multi-turn conversation messages in a readable chat format, filter examples by review state, accept or reject individual examples, edit message JSON, and execute bulk curation actions.

---

## 2. Test Cases & Procedures

### TC-005.1: Chat Conversation Rendering
* **Objective:** Verify multi-turn chat messages render with distinct sender badges and formatted content.
* **Procedure:**
  1. Open a dataset containing user and assistant messages (e.g. `/projects/:project_id/datasets/:id`).
  2. Inspect the rendered DOM for each message turn.
* **Expected Result:**
  - User messages display `U` icon with blue styling.
  - Assistant messages display `A` icon with purple styling.
  - System messages display `S` icon with gray styling.
  - Multi-line text retains line breaks via `whitespace-pre-wrap`.

### TC-005.2: State Filtering (Tabs)
* **Objective:** Verify filtering between `All`, `Accepted`, `Rejected`, `Needs Review`, and `Errors`.
* **Procedure:**
  1. Click the **Accepted** tab (`?filter=accepted`). Verify only `accepted: true` examples appear.
  2. Click the **Rejected** tab (`?filter=rejected`). Verify only `accepted: false` examples appear.
  3. Click **Needs Review** (`?filter=needs_review`). Verify only `accepted: nil` examples appear.
  4. Click **Errors** (`?filter=errors`). Verify only examples with validation errors appear.
* **Expected Result:**
  - Selected tab highlights with indigo background.
  - Counters at top accurately reflect category counts (`accepted_count`, `rejected_count`, etc.).

### TC-005.3: Individual Example Review Actions
* **Objective:** Verify single-item Accept, Reject, Edit, and Delete actions.
* **Procedure:**
  1. Click **Accept** on a `Needs Review` example (`POST .../dataset_examples/:id/accept`).
     - Example state updates to `accepted: true` with green badge.
  2. Click **Reject** on an example (`POST .../dataset_examples/:id/reject`).
     - Example state updates to `accepted: false` with red badge.
  3. Click **Edit** (`GET .../dataset_examples/:id/edit`).
     - JSON textarea displays formatted messages. Edit text and submit.
     - Updated content persists in SQLite.
  4. Click **Delete** (`DELETE .../dataset_examples/:id`).
     - Example record is removed; counter decreases by 1.

### TC-005.4: Bulk Curation Actions via Stimulus
* **Objective:** Verify the `bulk-select` Stimulus controller and bulk submission endpoint.
* **Procedure:**
  1. Check the **Select All** checkbox in the curation header.
  2. Verify all individual checkboxes check and bulk action buttons appear (`Accept Selected`, `Reject Selected`, `Delete Selected`).
  3. Click **Accept Selected** (`POST .../dataset_examples/bulk_action` with `bulk_action=accept`).
* **Expected Result:**
  - All selected records update `accepted: true`.
  - Flash message confirms: `"N examples accepted."`.

### TC-005.5: Pagination
* **Objective:** Verify Pagy pagination operates cleanly over large datasets (default 25 items per page).
* **Procedure:**
  1. Load a dataset with 30+ examples.
  2. Verify pagination bar displays `Showing 1-25 of 30`.
  3. Click **Next** or page `2`.
* **Expected Result:**
  - Page 2 loads remaining items. Previous/Next links function correctly.

---

## 3. Pass / Fail Acceptance Criteria

- [ ] Chat conversation bubbles render accurately for user/assistant roles.
- [ ] Tab filters (`accepted`, `rejected`, `needs_review`, `errors`) isolate correct record subsets.
- [ ] Editing messages JSON validates input before saving.
- [ ] Bulk accept, bulk reject, and bulk delete operate atomically.
- [ ] All tests in `test/integration/datasets_flow_test.rb` pass.
