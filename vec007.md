# VEC-007: Live Training Lifecycle, Metrics & Monitoring Verification

**Identifier:** `VEC-007`  
**Category:** Training Execution & Real-Time Monitoring  
**Target Systems:** `TrainingRunsController`, `Api::V1::TrainingCallbacksController`, `TrainingRunPollJob`, `TrainingRunCancelJob`, Stimulus `polling_controller.js`, `chart_controller.js`, `TrainingMetric` Model  

---

## 1. Objective

Verify the complete training run lifecycle (`pending` ➔ `queued` ➔ `running` ➔ `completed` / `failed` / `cancelled`), real-time metric ingestion via worker callbacks and polling fallbacks, live dynamic canvas chart rendering of loss over steps, and safe job cancellation.

---

## 2. Test Cases & Procedures

### TC-007.1: Status Transitions & Timestamps
* **Objective:** Ensure status transitions accurately record start and completion timestamps.
* **Procedure:**
  1. Trigger status transition `pending` ➔ `queued` (`queue!`).
  2. Transition to `running` (`start!`). Verify `started_at` is set to `Time.current`.
  3. Transition to `completed` (`complete!`). Verify `finished_at` is set.
  4. Verify `formatted_duration` calculates elapsed time (e.g. `32m 14s`).
* **Expected Result:**
  - Status badges accurately display in UI: `QUEUED` (blue), `RUNNING` (yellow), `COMPLETED` (green).

### TC-007.2: Real-time Metric Ingestion via Callbacks
* **Objective:** Verify `POST /api/v1/training_callbacks/:id/metrics` logs individual steps and updates training run summary.
* **Payload:**
  ```json
  {
    "step": 150,
    "epoch": 2.0,
    "loss": 0.7421,
    "learning_rate": 0.0001
  }
  ```
* **Procedure:**
  ```bash
  curl -s -X POST http://localhost:3000/api/v1/training_callbacks/:training_run_id/metrics \
    -H "Content-Type: application/json" \
    -H "X-API-Key: dev-worker-key" \
    -d '{"step": 150, "epoch": 2.0, "loss": 0.7421, "learning_rate": 0.0001}'
  ```
* **Expected Result:**
  - HTTP `200 OK` with `{"status": "ok"}`.
  - New `TrainingMetric` created.
  - `training_run.metrics` updated with `latest_step`, `latest_epoch`, `latest_loss`.

### TC-007.3: Polling Controller Auto-Refresh
* **Objective:** Verify Stimulus `polling_controller.js` polls `metrics` endpoint every 5 seconds while active, and terminates upon completion.
* **Procedure:**
  1. Inspect DOM on active run: contains `data-controller="polling"` and `data-polling-url-value=".../metrics.json"`.
  2. Simulate worker completing the run.
  3. Check polling response JSON: contains `status: "completed"`.
* **Expected Result:**
  - Stimulus polling controller clears interval (`stopPolling()`) and triggers a page refresh to display final completion artifacts.

### TC-007.4: Dynamic Canvas Loss Chart
* **Objective:** Verify Stimulus `chart_controller.js` draws an interactive HTML5 canvas graph for step vs. loss.
* **Procedure:**
  1. Open a completed training run containing multiple metrics (e.g. seed experiment with 75 steps).
  2. Inspect the chart canvas element.
* **Expected Result:**
  - Canvas renders dark background (`#1f2937`), gridlines, step labels on X-axis, loss values on Y-axis, and an indigo plot line (`#818cf8`) connecting consecutive step/loss pairs.

### TC-007.5: Safe Training Cancellation
* **Objective:** Verify an active training run can be cancelled via the UI.
* **Procedure:**
  1. On an active run, click **Cancel Training** (`POST .../training_runs/:id/cancel`).
  2. `TrainingRunCancelJob` signals the Python worker and marks status as `cancelled`.
* **Expected Result:**
  - Run status becomes `cancelled`.
  - UI shows `CANCELLED` badge.
  - Worker's `MetricsCallback.should_stop` flag is set to `True`, aborting the training loop.

---

## 3. Pass / Fail Acceptance Criteria

- [ ] Lifecycle transitions follow: `pending` ➔ `queued` ➔ `running` ➔ `completed`/`failed`/`cancelled`.
- [ ] Metric callbacks store `step`, `epoch`, `loss`, `learning_rate` without data loss.
- [ ] Canvas chart plots steps and loss points correctly.
- [ ] Polling stops when terminal state is reached.
- [ ] Cancellation halts training gracefully.
- [ ] All tests in `test/models/training_metric_test.rb` and `test/integration/api_callbacks_test.rb` pass.
