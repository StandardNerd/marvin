# VEC-003: Project Lifecycle & Base Model Management Verification

**Identifier:** `VEC-003`  
**Category:** Domain Management & Modeling  
**Target Systems:** `ProjectsController`, `Project` Model, `Project` Views  

---

## 1. Objective

Verify project creation, modification, validation, deletion, and configurable default base model behavior (e.g. `Qwen/Qwen3-8B`), ensuring that projects act as the top-level container for all datasets and experiments.

---

## 2. Test Cases & Procedures

### TC-003.1: Configurable Default Base Model
* **Objective:** Verify that `ENV['DEFAULT_BASE_MODEL']` or app configuration populates the default base model on new projects.
* **Procedure:**
  1. Navigate to `/projects/new`.
  2. Inspect the `Base Model` input field value.
* **Expected Result:**
  - Field is pre-populated with `Qwen/Qwen3-8B` (or configured value in `ENV['DEFAULT_BASE_MODEL']`).

### TC-003.2: Project Validations
* **Objective:** Ensure projects require non-empty `name` and `base_model`.
* **Procedure:**
  1. Submit POST `/projects` with `{ project: { name: "", base_model: "" } }`.
* **Expected Result:**
  - Status: HTTP 422 Unprocessable Entity.
  - Form re-renders with error messages: `"Name can't be blank"`, `"Base model can't be blank"`.

### TC-003.3: Project Dashboard Listing & Counter Summary
* **Objective:** Verify `/projects` lists only projects belonging to `current_user` and accurately displays dataset and experiment counts.
* **Procedure:**
  1. Navigate to `/projects`.
  2. Verify project card displays:
     - Project name and description.
     - Number of datasets (`project.datasets.count`).
     - Number of experiments (`project.training_runs.count`).
     - Base model identifier badge.

### TC-003.4: Project Deletion & Cascading Behavior
* **Objective:** Verify deleting a project cleanly cascades to associated datasets and training runs.
* **Procedure:**
  1. Create a project with 1 dataset and 1 training run.
  2. Send DELETE `/projects/:id`.
* **Expected Result:**
  - Project record is destroyed.
  - Dependent `Dataset` and `TrainingRun` records are destroyed (`dependent: :destroy`).
  - User redirected to `/projects` with notice `"Project deleted."`.

---

## 3. Pass / Fail Acceptance Criteria

- [ ] Project cannot be created without `name` and `base_model`.
- [ ] New project form defaults to `DEFAULT_BASE_MODEL`.
- [ ] Project show page shows child datasets and experiments tables.
- [ ] Automated tests in `test/models/project_test.rb` and `test/integration/projects_flow_test.rb` pass with 0 failures.
