# VEC-008: Model Evaluation & Experiment Comparison Verification

**Identifier:** `VEC-008`  
**Category:** Evaluation & Experiment Analysis  
**Target Systems:** `EvaluationsController`, `ExperimentsController`, `EvaluationJob`, `Api::V1::EvaluationCallbacksController`, Python Worker `ModelEvaluator`  

---

## 1. Objective

Verify that fine-tuned adapters can be evaluated against the base model using simple, transparent evaluation metrics (exact match rate and difflib text similarity), that evaluations display appropriate quality disclaimers, and that multiple experiments can be compared side-by-side with visual configuration diff highlighting.

---

## 2. Test Cases & Procedures

### TC-008.1: Creating and Launching an Evaluation
* **Objective:** Verify creating an evaluation against a test dataset enqueues `EvaluationJob`.
* **Procedure:**
  1. From a completed training run, click **Run Evaluation**.
  2. Enter evaluation name and select evaluation dataset.
  3. Submit POST `/projects/:project_id/training_runs/:training_run_id/evaluations`.
* **Expected Result:**
  - Status is set to `pending`.
  - `EvaluationJob` is queued.
  - User redirected to evaluation show page with status badge `PENDING` / `RUNNING`.

### TC-008.2: Evaluation Completion & Callback Processing
* **Objective:** Verify `POST /api/v1/evaluation_callbacks/:id/complete` records aggregate metrics and per-example outputs.
* **Payload:**
  ```json
  {
    "metrics": {
      "exact_match": 0.20,
      "text_similarity": 0.72,
      "aggregate_score": 0.46,
      "total_examples": 10,
      "note": "Basic evaluation metrics. Not a comprehensive measure of LLM quality."
    },
    "results": [
      {
        "input": "How do I upgrade?",
        "expected": "Go to Settings > Billing",
        "actual": "Go to Settings > Billing > Change Plan",
        "exact_match": false,
        "similarity": 0.81
      }
    ]
  }
  ```
* **Procedure:**
  ```bash
  curl -s -X POST http://localhost:3000/api/v1/evaluation_callbacks/:eval_id/complete \
    -H "Content-Type: application/json" \
    -H "X-API-Key: dev-worker-key" \
    -d '<payload>'
  ```
* **Expected Result:**
  - `Evaluation` record updates: `status: "completed"`, `metrics: {...}`, `results: [...]`.
  - UI displays aggregate percentage scores, per-example diff cards, and the required quality disclaimer.

### TC-008.3: Evaluation Quality Metric Disclaimer
* **Objective:** Ensure the UI and API explicitly communicate that exact match and simple similarity are basic metrics and not comprehensive LLM benchmarks.
* **Verification:**
  - Inspect `evaluations/show.html.erb` and `experiments/compare.html.erb`.
  - Both templates must display the notice:
    > "⚠ These are basic evaluation metrics. They provide a rough comparison but are not comprehensive measures of LLM quality."

### TC-008.4: Multi-Experiment Comparison Matrix
* **Objective:** Verify comparing 2+ experiments side-by-side renders an aligned table with diff highlighting.
* **Procedure:**
  1. Navigate to `/experiments`.
  2. Select 2 or more experiments using checkboxes or visit `/experiments/compare?ids=1,2`.
  3. Inspect the comparison table.
* **Expected Result:**
  - Table headers list experiment names and projects.
  - Rows display: Status, Base Model, Dataset, Duration, Final Loss.
  - Configuration section highlights keys whose values differ between experiments with a yellow background and a `differs` tag.
  - Completed evaluation metrics appear in a shared comparative section.

---

## 3. Pass / Fail Acceptance Criteria

- [ ] Evaluations compute and store `exact_match`, `text_similarity`, and `aggregate_score`.
- [ ] Evaluation show page lists input, expected output, and generated output per example.
- [ ] Comparison page highlights configuration differences between runs in contrasting yellow styling.
- [ ] Disclaimer alert is prominently visible on all evaluation views.
- [ ] All tests in `test/models/evaluation_test.rb` and `test/integration/experiments_flow_test.rb` pass.
