# VEC-002: Authentication, Security & Tenant Isolation Verification

**Identifier:** `VEC-002`  
**Category:** Security, Auth & Authorization  
**Target Systems:** `UsersController`, `SessionsController`, `RegistrationsController`, `Api::V1::BaseController`, Models (`User`, `Project`)  

---

## 1. Objective

Ensure that user accounts are properly authenticated, passwords are securely hashed using bcrypt, sessions are managed safely, cross-tenant project data is strictly isolated, and inter-service API endpoints require authenticated API keys.

---

## 2. Test Cases & Procedures

### TC-002.1: User Registration Flow
* **Objective:** Verify new users can register with valid parameters and are rejected on invalid inputs.
* **Procedure:**
  1. POST to `/signup` with:
     ```ruby
     { user: { name: "Test Engineer", email: "engineer@example.com", password: "password123", password_confirmation: "password123" } }
     ```
  2. Verify user is persisted, password digest is created with bcrypt, and session is established (`redirect_to /projects`).
  3. POST duplicate email `engineer@example.com`.
* **Expected Result:**
  - Duplicate registration fails with HTTP 422 Unprocessable Entity and error: `"Email has already been taken"`.

### TC-002.2: Session Authentication & Protected Routes
* **Objective:** Ensure unauthenticated requests to protected endpoints redirect to `/login`.
* **Procedure:**
  ```bash
  curl -s -i http://localhost:3000/projects
  ```
* **Expected Result:**
  - HTTP Status: `302 Found`
  - `Location: http://localhost:3000/login`

### TC-002.3: Cross-User Project & Resource Isolation
* **Objective:** Verify User A cannot read, edit, or delete User B's projects, datasets, training runs, or model artifacts.
* **Procedure:**
  1. Create Project 1 owned by User 1.
  2. Log in as User 2.
  3. Attempt GET `/projects/:project_1_id`.
  4. Attempt DELETE `/projects/:project_1_id`.
* **Expected Result:**
  - Controller scopes lookups through `current_user.projects.find(params[:id])`.
  - Rails raises `ActiveRecord::RecordNotFound` or responds with HTTP 404. User 2 cannot access or mutate User 1's resources.

### TC-002.4: ML Worker API Key Authentication
* **Objective:** Ensure Rails callback endpoints reject unauthorized worker requests and accept valid API keys.
* **Procedure:**
  ```bash
  # Attempt without header
  curl -s -i -X POST http://localhost:3000/api/v1/training_callbacks/1/metrics \
    -H "Content-Type: application/json" \
    -d '{"step": 1, "loss": 1.5}'

  # Attempt with valid header
  curl -s -i -X POST http://localhost:3000/api/v1/training_callbacks/1/metrics \
    -H "Content-Type: application/json" \
    -H "X-API-Key: dev-worker-key" \
    -d '{"step": 1, "loss": 1.5}'
  ```
* **Expected Result:**
  - Request 1: Returns HTTP `401 Unauthorized` with `{"error": "Unauthorized"}`.
  - Request 2: Authenticates via `ActiveSupport::SecurityUtils.secure_compare` and returns HTTP `200 OK`.

### TC-002.5: Secure Shell & Input Sanitization
* **Objective:** Ensure user inputs (model names, dataset filenames, hyperparameter values) are never passed to shell exec or string interpolation in commands.
* **Verification:**
  - Codebase inspection verifies no usage of `Kernel.system`, `exec`, or backtick interpolation with user parameters.

---

## 3. Pass / Fail Acceptance Criteria

- [ ] Unauthenticated requests to `/projects`, `/experiments`, `/model_artifacts` redirect to `/login`.
- [ ] Passwords stored strictly as bcrypt hashes in `password_digest` column.
- [ ] Users can only access resources where `project.user_id == current_user.id`.
- [ ] API endpoints return 401 when `X-API-Key` is missing or mismatched.
- [ ] All automated tests in `test/integration/authentication_test.rb` and `test/integration/security_test.rb` pass.
