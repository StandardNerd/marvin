# VEC-010: Automated Test Suite & Data Persistence Verification

**Identifier:** `VEC-010`  
**Category:** Quality Assurance, Persistence & Reliability  
**Target Systems:** Entire Application Test Suite (Minitest), SQLite Database, Demo Seed Script (`db/seeds.rb`)  

---

## 1. Objective

Verify that the entire automated test suite passes without requiring a GPU, that SQLite database persistence maintains state across server or container restarts without metadata loss, and that the demo seed data provisions a realistic, functioning environment for evaluation.

---

## 2. Test Cases & Procedures

### TC-010.1: Full Minitest Suite Execution (GPU-Independent)
* **Objective:** Verify all unit, job, and integration tests execute successfully without an external Python worker or GPU hardware.
* **Procedure:**
  ```bash
  rails test
  ```
* **Expected Result:**
  - Test suites execute:
    - Unit Models: `User`, `Project`, `Dataset`, `DatasetExample`, `TrainingRun`, `TrainingMetric`, `Evaluation`, `ModelArtifact`
    - Jobs: `DatasetProcessingJob`
    - Integration: `AuthenticationTest`, `SecurityTest`, `ProjectsFlowTest`, `DatasetsFlowTest`, `TrainingRunsFlowTest`, `ExperimentsFlowTest`, `ApiCallbacksTest`
  - Output summary:
    ```text
    77 runs, 128 assertions, 0 failures, 0 errors, 0 skips
    ```

### TC-010.2: SQLite Data Persistence Across Restarts
* **Objective:** Ensure projects, datasets, training metrics, and artifacts persist to disk and survive application restarts.
* **Procedure:**
  1. Boot the application and verify record counts:
     ```bash
     rails runner 'puts "Projects: #{Project.count}, Runs: #{TrainingRun.count}"'
     ```
  2. Stop the Rails server or restart the Docker container (`docker compose restart rails`).
  3. Verify database file exists at `storage/development.sqlite3`.
  4. Query the database again.
* **Expected Result:**
  - Record counts and IDs remain identical before and after restart.
  - JSON columns (`messages`, `configuration`, `metrics`, `results`) retain structured keys and values without corruption.

### TC-010.3: Seed Data Initialization
* **Objective:** Verify `rails db:seed` executes idempotently and provisions a full interactive demo environment.
* **Procedure:**
  ```bash
  rails db:seed
  ```
* **Expected Result:**
  - Creates demo account: `demo@example.com` / `password123`.
  - Creates project: `Customer Support Bot`.
  - Creates dataset: `support-conversations-v1` with 25 example conversations.
  - Creates completed training run: `support-qlora-v1 (demo)` with 75 steps of simulated training metrics.
  - Creates evaluation: `Evaluation - Demo`.
  - Creates registered model artifact: `support-assistant v1`.
  - Script output clearly reminds the user: *"Training runs marked as 'demo' do not represent real trained models."*

### TC-010.4: Codebase Lint & Integrity Check
* **Objective:** Verify all Ruby and Python files are syntactically sound and have no syntax errors or unresolved requires.
* **Procedure:**
  ```bash
  rails runner 'puts "All Ruby classes load cleanly"'
  python3 -m py_compile ml_worker/app/*.py ml_worker/training/*.py ml_worker/evaluation/*.py
  ```
* **Expected Result:**
  - Exit code `0` with no syntax errors.
